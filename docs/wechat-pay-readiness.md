# 微信支付审核通过前准备清单

当前状态：微信支付商户关联仍在审核中。生产环境必须保持支付入口关闭；不得使用 mock、跳过验签或人工修改订单为已支付。

## 已准备

- 订单金额只从在售会员卡商品读取，前端不能传入价格。
- `Idempotency-Key` 与会员组成唯一约束，重复创建返回同一订单。
- 订单保存完整商品快照，后续改名、改价、下架不影响历史订单。
- 待支付订单 30 分钟过期，读取时自动关闭。
- 会员只能查看自己的订单。
- 小程序商品详情、订单列表和订单详情已经接好；支付按钮保持审核中状态。
- 支付准备接口在审核期间固定返回 `WECHAT_PAY_UNDER_REVIEW`，不会创建支付流水或扣款。

## 审核通过后需要提供并配置

以下值只能放在服务器 Secret 或权限为 `600` 的生产环境文件中，不得提交到 Git：

- 微信支付商户号 `WECHAT_PAY_MCH_ID`
- API v3 密钥 `WECHAT_PAY_API_V3_KEY`
- 商户证书序列号 `WECHAT_PAY_CERT_SERIAL_NO`
- 商户 API 私钥文件 `WECHAT_PAY_PRIVATE_KEY_PATH`
- 支付通知地址 `https://api.urockclimbing.cn/api/v1/payments/wechat/notify`
- 微信支付平台证书或平台公钥 ID/公钥（按届时官方方案配置）

## 审核通过后的实现与验收顺序

1. 使用微信支付 API v3 JSAPI 下单，`openid` 仅由服务端身份关联读取。
2. 服务端生成 `wx.requestPayment` 所需 RSA 签名参数。
3. 实现支付通知验签、解密，并严格校验 AppID、商户号、订单号、币种和金额。
4. 在同一 MySQL 事务中将支付流水置为成功、订单置为 `PAID` 并发放一张会员卡。
5. 重复通知必须返回成功但不得重复发卡。
6. 实现订单主动查询；小程序支付返回只触发查询，不直接发卡。
7. 完成支付失败、取消、超时、重复点击、重复通知、金额不一致和跨用户访问测试。
8. 在独立体验数据库完成真机小额支付与退款，再部署生产。

## 上线门禁

只有同时满足以下条件，才能把小程序 `paymentEntryEnabled` 改为 `true`：

- 商户关联审核通过，JSAPI 支付权限可用；
- 生产 Secret 配置完整，私钥文件权限正确；
- 支付下单、通知验签、事务发卡和主动查询代码已部署；
- MySQL 集成测试及 `make check` 通过；
- 体验版真机支付成功，且重复通知只发一张卡；
- 回调域名、服务器时间、HTTPS 证书和告警均正常。
